# PVZ 系列 · 子站目录

这里是 `01guo.com/pvz/` 的全部内容，PVZ 系列长期就住在这个子目录里（**不再搬去独立子域名**，
原因见文末「子域名」一节）。主站首页只留一条横幅指进来。

**这一页仍按"站点首页"排，不按"入口页"排** —— 首屏讲清这是什么，再往下是三条产品行与花田。

## 文件

| 文件 | 是什么 |
|---|---|
| `index.html` | 站点首页：三条产品行（图 / 正文 / 事实栏）+ 花田横幅。版本、体积、平台、最新日期全部现读，不写死。 |
| `player.html` | PVZ Player 详情页。按 `id=P733` 从 `../softwares.js` 取版本号、下载地址、截图。 |
| `editor.html` | 关卡编辑器详情页。按 `id=650379` 取同样的东西。 |
| `launcher.html` | 启动器详情页。样式与 `player.html` 同源（同一套 hero / stats / 功能卡 / 图集 / 下载区），只换配色。内容压到 3 张功能卡，其余全读 `softwares.js`。 |
| `charge.html` | 花田（项目充能墙）。读 `data/patrons.json` 与 `data/groups.json`。 |
| `bg-lawn.jpg` | 花田页的草坪底图（模糊垫在玻璃底下）。 |
| `data/*.json` | **唯一真身**。CMS「官方群组」「赞助者名单」导出就写这里，PVZ Player 客户端也读这里。 |

**Player_PvZ · 兼容性修复启动器**（`id=982702`）的 `launcher.html` 是拿 `player.html` 派生出来的
（`Dream_CMS\_官网重构\tools\make_launcher.py`，不是手抄）—— 同一套 DOM 骨架与 CSS，只换配色令牌。

内容上做小：3 张功能卡，不铺 9 张。图片、版本、体积、下载地址**全部读 `softwares.js`**，
CMS 里改了 `detailImages` 这边图集就跟着变，不用动代码；`description` 填了之后，
末尾那行会顶到下载区做说明，整段会显示成"更新日志"（跟 player.html 完全一样的行为）。

## 几条不能破的规矩

1. **不要手改 `data/*.json`**。那是 CMS 导出的产物，手改下次导出就被覆盖。要改去 CMS 改。
2. **不要在页面里再抄一份名单**。以前群号和赞助者有三处手抄，改一处忘两处，线上永远是旧的。
   页面上要显示名单，只允许 `fetch('data/xxx.json')`。
3. **不引 `assets/*.js`**。那套字段名（`people` / `n` / `t`）跟 CMS 契约（`patrons` / `name` / `tier`）
   是两套，两套并存迟早对不上。`charge.html` 里只做一次字段映射。
4. **不放「畅玩机」独立卡片**。畅玩机是 PVZ Player 里的一个窗口，不是单独下载的东西。
   给它一张卡会让人以为要另外下个安装包。反过来，**启动器单独成一行**是对的 ——
   它自己就是一个安装包，而且不装它也能玩。
5. **新增页面一律用相对路径**（`data/xxx.json`、`bg-lawn.jpg`），不要写 `/assets/xxx`。
   页面永远和 `data/` 同目录，相对路径最稳，将来真要整体搬家也不会断。
   （`tools/to_subdomain.py` 仍留着，但它只服务于"改主意搬子域"那条已放弃的路线，日常不用跑。）
6. **页脚不放「← 返回主站 / 返回系列」的文字链接，只放友情链接。**
   友情链接读 `softwares.js` 的 `friendLinks`（跟主站 footer 同一份数据、同一套胶囊），
   **指向当前页所在目录的那条自动跳过**：在 `01guo.com/pvz/` 各页里只显示指回主站的「dream」，
   「PVZ Player」（指向本目录 `/pvz/`）跳过。判据是"域名 + 目录"而不是只看域名 ——
   主站和 `/pvz/` 同域，只看域名会把两条一起跳过，页脚就整块消失了。
   回系列首页的动作由导航 logo 承担（`href="index.html"`），
   回主站的动作由导航右上角的「主站 ↗」承担 —— 底部再说一遍就是同一个出口开三次。

## 子域名 pvz.01guo.com：为什么最后没做

> 这一节把前因后果记下来，免得以后（包括我）又重走一遍这条弯路。

### 起因

PVZ 系列原本想要一个独立门牌 `pvz.01guo.com`：比 `01guo.com/pvz/` 短，也更像"一个独立站点"。

### 当时做了什么（技术上都通了）

- 写了搬迁脚本 `tools/to_subdomain.py`：把 `pvz/` 复制成一个独立站点根目录，把"上一级"的相对引用改成绝对地址。
  每条改写规则都**断言预期命中次数**，源文件一改、次数对不上就当场报错，不会静默漏掉一条路径。
- 验证了跨域可行性：GitHub Pages 对静态资源一律回 `Access-Control-Allow-Origin: *`（`curl -I` 实测），
  所以子站能跨域读主站的 `assets/*.css`、`softwares.js`、`logo/*`、`update/*.json`，不需要任何 CORS 配置。
  数据层（`pvz/data/*.json`）继续留在主站，CMS 与 PVZ Player 客户端都不用改。
- DNS 也配好了：阿里云加了一条 `pvz` 的 `CNAME → yiguo666.github.io`，
  `nslookup` 实测解析到 `185.199.108~111.153`，跟 `01guo.com` 是同一批 IP。

### 卡在哪（"解析出问题"的真相）

DNS 没错，错在 **GitHub 那边根本没有这个站**：

- `http://pvz.01guo.com/` 回的是 `404 · There isn't a GitHub Pages site here`；
- `https://` 拿到的是 `CN=*.github.io` 的兜底证书，浏览器直接报"证书不安全 / 域名不匹配"；
- GitHub 账号名下只有 `dream`、`nox` 两个仓库，没有 pvz 仓库。

⇒ **DNS 只是"指路"，站得先在 GitHub 建仓 + 在 Settings→Pages 里声明 Custom domain 才会有人应答。**
只加 DNS 的典型症状就是"能解析、但敲开是 404 / 证书不对"，别去反复改 DNS 记录。

### 为什么最终放弃

把成本收益摆平了看，**不划算**：

| | 留在主仓库 `/pvz/`（现状） | 单开子域 |
|---|---|---|
| 页面、详情页、CMS | 已经全跑通 | 一样，但要多维护一套 |
| URL 观感 | 稍长 | 更短（**唯一收益**） |
| 额外成本 | 无 | 单独建仓 + 单独部署 + 自定义域 + 等 Let's Encrypt 签证书（证书下来前浏览器一直报"不安全"） |
| 对 CMS 的帮助 | 数据就在主仓库，天然可管 | **零**（`softwares.js` 仍在主仓库，子站要么跨域读、要么复制一份） |

而且主站 ↔ PVZ 之间本来就能用链接互跳。独立域名带来的"独立感"是纯装饰性的，不值这份维护成本。
**少主拍板：不做子域名，PVZ 永久留在 `01guo.com/pvz/`，并已删除那条 `pvz` 的 DNS CNAME 记录。**

### 结论与遗留

- `pvz.01guo.com` 现在**不再解析**（DNS 记录已删），这个地址作废。
- `tools/to_subdomain.py` 保留着没删 —— 真要哪天改主意，一条命令生成 + 三步手动（建仓、Pages 声明域名、加 DNS）。
  但**不要**为了"看着独立"去做，成本不对等。
- 连带的代码调整（已做，别改回去）：
  - `softwares.js` 的 `friendLinks` 里「PVZ Player」原来指向 `pvz.01guo.com`，子域作废后改指 **`https://01guo.com/pvz/`**；
  - `pvz/*.html` 页脚的友链去重从"按 hostname"改成"**按目录**"：在 `/pvz/` 里就跳过指向 `/pvz/` 的那条、
    只留指回主站的「dream」；在别处则相反。否则同域名的两条会一起被跳过（页脚整块消失），或把用户指回自己当前这一页。
